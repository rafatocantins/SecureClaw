# SQL Injection Audit Report — 2026-07-08

**Project:** Tessera  
**Audit scope:** All packages with SQLite database access  
**Auditor:** Automated security review (PATT-003)  
**Conclusion:** ✅ No SQL injection vulnerabilities after corrections

---

## Packages audited

### 1. audit-system (`packages/audit-system`)
- **Total queries:** 22
- **Parameterization:** All queries use `?` placeholders with prepared statements ✅
- **Verdict:** PASS — no injection surface

### 2. memory-store (`packages/memory-store`)
- **Total queries:** 18
- **Parameterization:** 15 queries use `?` placeholders ✅
- **⚠️ 3 queries use FTS5 MATCH with user-supplied input:**
  - `searchMessages()` — `fts.messages_fts MATCH ?` (inline prepared statement)
  - `getRelevantLessons()` — `fts.lessons_fts MATCH ?` (compiled prepared statement)
  - One additional FTS5 MATCH query in vector scoring path
- **Mitigation applied:** Added `sanitizeFts5Query()` in `packages/memory-store/src/fts5-sanitizer.ts` that:
  - Escapes double quotes (FTS5 convention: `"` → `""`)
  - Strips wildcard prefix/suffix operators (`*hello*` → `hello`)
  - Removes standalone asterisks
  - Wraps multi-word or operator-containing queries in double quotes to treat as literal phrases
  - Rejects empty queries
- **Verdict:** PASS after corrections ✅

### 3. credential-vault (`packages/credential-vault`)
- **Total queries:** 6
- **Parameterization:** All queries use `?` placeholders ✅
- **Verdict:** PASS — no injection surface

## New security function

| Function | Location | Purpose |
|---|---|---|
| `sanitizeFts5Query()` | `packages/memory-store/src/fts5-sanitizer.ts` | Escapes/removes FTS5 special syntax from user-supplied search queries to prevent query injection via FTS5 operators (`AND`, `OR`, `NOT`, `NEAR`, `*`, `"`) |
